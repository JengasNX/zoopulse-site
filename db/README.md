# Серверный фундамент

`migrations/001_core.sql` — первая схема PostgreSQL для сквозного MVP.
Миграция ещё НЕ применена: PostgreSQL и доступы к отдельной БД не настроены.
Наличие SQL не означает работающий backend.

Порядок:
1. Выделить пустую локальную dev-БД PostgreSQL 15+ и отдельную test-БД.
2. Настроить поддерживаемую авторизацию и её миграции.
3. Выбрать runner с журналом/контрольными суммами миграций.
4. Применить схему и проверить ограничения в интеграционных тестах.
5. Использовать отдельного непривилегированного пользователя приложения;
   определить grants/RLS и серверные политики доступа.
6. Не запускать на существующих пользовательских базах и не выдавать
   приложению права владельца схемы.

Особенности: неизвестные медицинские сведения — NULL, не false;
заявки защищены ключом повторной отправки; уведомления отделены от сохранения;
частные контакты не входят в аудит. Сроки хранения и удаление предстоит
оформить с оператором данных до реального использования.
